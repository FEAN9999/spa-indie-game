# Phây lô B Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Phây two things to do: answer a complaint (the right reply lifts that customer's scores to 4) and pay to boost a post (more customers and tips the next day, more followers).

**Architecture:** Rules live in the sim: `src/sim/feed.ts` grows the pure parts (reply effects on a post, boost prices, the boost list), `SpaSim` gets `answerPost` and `boostPost` plus the next-day effects in its arrival, patience, tip and `recordDay` paths. `PhayScene` gets the two buttons and two cards; the morning line comes from `src/view/events.ts`. Save stays 36.

**Tech Stack:** TypeScript, Phaser 4, Vitest, Vite.

**Spec:** `docs/superpowers/specs/2026-10-31-phay-design.md` (4.9, 4.10, 4.11, 7, 8). Lô A is live (origin/master 1890ef1).

## Global Constraints

- Save version stays **36**; no field of lô A changes meaning. The one addition, `post` on a boost entry, is optional on read (missing → 0) so the lô A build keeps reading lô B saves.
- Every Phây draw uses its own stream (`feedRng(salt)` / `guestRng(c, salt)`, salts < 16; news salts 7–15 are taken, so lô B uses `feedRng` with salts listed in its task); never `this.rng`. `tests/sim/same-draws.test.ts` passes unchanged — a day with no boost draws exactly as before.
- Replies: right → every score of that customer still in the 20-score window becomes **4**, the post shows 4★; plain → **3**, 3★; rude → scores unchanged, post becomes drama (more likes and comments). No followers lost, no money lost, no expiry, one answer per post.
- Boost tiers (price = share × `awayMean`, rounded **up** to 10.000 đ, never under the minimum; a mean ≤ 0 pays the minimum):
  - small: 22,5 %, min 150.000 đ; next day arrivals ×1,15, tips ×1,1
  - medium: 60 %, min 450.000 đ; arrivals ×1,3, tips ×1,2
  - large: 120 %, min 900.000 đ; arrivals ×1,5, tips ×1,3
- A boost works **only the next day, only at the main shop**. One boost a day. The arrival factor multiplies on top of `eventArrivalFactor()`'s `min` (festival/hot), patience ×`FESTIVAL_PATIENCE` on that day, the day counts as busy in `recordDay`, the tip factor sits beside `POWER_TIP_FACTOR` before the generous tip.
- Boost buttons on praise posts and the shop's own posts only (`boostable`). Prices are anh's (×1,5); the builder measures profit per tier and reports it, never changes prices.
- Text Vietnamese, no emoji. Copy lines (exact): toast "Hôm nay đã đẩy một bài rồi. Mai đẩy tiếp nha."; label "Đang đẩy"; buttons "Trả lời", "Đẩy bài", "Để sau"; morning line "Hôm nay bài đẩy đang chạy, khách đông hơn".

## Review Focus

1. Owner at a branch answers or boosts: the complaint's customer and the money are the main shop's — the main shop's scores change, the purse pays, the boost runs at the main shop only. (Task 2 and 3 tests.)
2. Boost on two days in a row: day d's boost still runs all of day d+1 after day d+1's purchase; the list never holds more than 2. (Task 3 test.)
3. A VIP's or star's three scores all change on a right reply; scores already out of the window change nothing but the post still flips. (Task 2 test.)
4. Reopening Phây after an answer or boost: the answered post shows the exchange and no Trả lời; the boosted post shows "Đang đẩy" the next day and "Đã đẩy" after; other boost buttons are dimmed for the rest of the day. (Task 4/5 browser check.)
5. Not enough money for a tier → that row is dimmed and a tap does nothing; a complaint saved by an older build with broken replies cannot be answered (no button) instead of crashing. (Task 1 repair test, Task 5 card.)

### Task 3: Boosting a post in the sim

**Files:**
- Modify: `src/config.ts`, `src/sim/feed.ts` (boost entry `post`, repair), `src/sim/spa.ts`
- Test: `tests/sim/feed-boost.test.ts`

**Interfaces:**
- Produces:
  ```ts
  // src/config.ts
  export const BOOST = {
    small: { share: 0.225, min: 150_000, arrival: 1.15, tip: 1.1, followers: 200 },
    medium: { share: 0.6, min: 450_000, arrival: 1.3, tip: 1.2, followers: 600 },
    large: { share: 1.2, min: 900_000, arrival: 1.5, tip: 1.3, followers: 1800 },
  } as const
  // src/sim/feed.ts
  export function boostPrice(tier: BoostTier, mean: number): number   // max(min, ceil(share × mean / 10_000) × 10_000); mean ≤ 0 → min
  export function boostedToday(feed: FeedBook, day: number): boolean   // a boost was bought today (an entry for day + 1)
  // FeedBook.boosts entries become { day: number; tier: BoostTier; post: number }  (repair: post missing/bad → 0)
  // src/sim/spa.ts (SpaSim)
  export type BoostProblem = 'missing' | 'notBoostable' | 'boosted' | 'today' | 'money'
  boostPrice(tier: BoostTier): number        // boostPrice(tier, awayMean(this.away)) on the main shop
  boostPost(postId: number, tier: BoostTier): BoostProblem | null
  boostTier(): BoostTier | null              // today's running boost: main shop only, entry with day === this.day
  ```
- Rules: `missing`/`notBoostable` (`!post.boostable`)/`boosted` (`post.boosted !== null`)/`today` (`boostedToday`)/`money` (`this.money < price`). Otherwise pay (`this.money -= price`, add the price to today's spend the way other purchases count in `stats` — follow `openFloor`'s or `buyHouse`'s pattern), `post.boosted = tier`, `post.likes += followers × 4`, push `{ day: this.day + 1, tier, post: postId }`, drop entries with `day < this.day`, keep at most 2, `growFollowers(BOOST[tier].followers)`.
- Next-day effects when `boostTier()` is a tier (all main-shop only, `place === null`): `eventArrivalFactor()` returns its old value `/ BOOST[tier].arrival`; `eventPatienceFactor()` returns `FESTIVAL_PATIENCE` on that day too; `recordDay(..., busy || boostTier() !== null, ...)`; the tip in `payFor` multiplies by `BOOST[tier].tip` next to the power factor.
- `startDay` also drops entries with `day < this.day`.

- [ ] **Step 1: Write failing tests:** `boostPrice`: mean 1.000.000 → small 230.000 (22,5 % = 225.000 → up to 230.000), medium 600.000, large 1.200.000; mean 100.000 → the minimums; mean −500.000 and 0 → minimums. `boostPost` problems each; `pays from the purse and marks the post`; `one boost a day` ('today' on a second post; next day allowed); `works only the next day`: arrival factor ×1 today, `/1,5` tomorrow (large), ×1 the day after; `with a festival` → festival factor / 1,3 (medium); `only the main shop`: a branch's `arrivalFactor()` unchanged on the boosted day; `patience and busy day`: a boosted day's new customer patience uses `FESTIVAL_PATIENCE`, `recordDay` sees busy (assert next month's targets unchanged vs. a run without the boost, or spy via progress bests); `tips`: a 3★ paid on the boosted day tips ×1,3 (large) vs. the same draw without; `two days in a row`: boost day d and day d+1 → day d+1 runs d's tier, day d+2 runs the second; list length ≤ 2; `followers grow and never fall`; `same-draws` unchanged with no boost; `repair`: entries without `post` read as `post: 0`.
- [ ] **Step 2: Run** `npx vitest run tests/sim/feed-boost.test.ts` — FAIL.
